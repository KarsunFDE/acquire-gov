## Scenario — "Cloud Managed Services BPA" (GSA-FAS, SDVOSB)

A relatable, services-based acquisition. Set-aside SDVOSB so Section K and the
consistency critic visibly react to the set-aside.

### Step 1 — Basics (paste these)

| Field | Value |
|---|---|
| Title | `Cloud Managed Services BPA — Hybrid Infrastructure Support` |
| Agency ID | `GSA-FAS` |
| NAICS | `541512` |
| Set-aside | **SDVOSB** |
| Contract type | **BPA** |
| Agency FAR supplement | `GSAM` |
| Notice type | **RFP** |
| Ceiling ($) | `12000000` |
| Period of performance | `12-month base period with four 12-month option periods` |
| Place of performance | `Washington, DC metro — hybrid, remote-eligible for non-privileged roles` |

| Key personnel required | `Program Manager, Cloud Architect, Information System Security Officer (ISSO)` |
| Description | `Enterprise managed services for hybrid cloud infrastructure: monitoring, patching, incident response, and FedRAMP-aligned security operations for GSA-FAS workloads.` |

### Step 2 — the one-button moment

Click **"Draft AI Parts"** (top batch bar). Talking point: *one click drafts
nine of twelve sections* — C, D, E, F, G, H, I (clauses), K, L, M. Only A
(cover form), B (CLINs/prices — a CO pricing judgment), and J (attachments) are
human-entered.

While it runs, narrate the architecture (see the diagram deck): C is drafted
first as the root; H/L/M are drafted against it; D-G + K are generated by a
cheap model (Haiku) from FAR templates; Section I clauses resolve
programmatically from the set-aside; the consistency critic runs last.

### Step 3 — walk the sections

Click through the stepper. Call out:
- **Section C (SOW)** — scope, background, requirements, performance standards.
- **Section K (Reps/Certs)** — note it lists **52.219-27** (SDVOSB notice) and
  **52.219-14** (Limitations on Subcontracting) — *the set-aside drove the
  clause selection*. Switch set-aside to Small Business in a second run and K
  changes to 52.219-6.
- **Section M (Eval)** — best-value tradeoff structure; switch to LPTA in Step 1
  and M visibly changes to pass/fail acceptability.
- **Step 7 Section I** — programmatically resolved clause list (no LLM).

### Step 4 — Review + edit (Step 12)

Every section A–M is shown in an editable box with a provenance badge
(ai / ai-edited / human). Edit Section C in front of the audience — the badge
flips to **ai-edited**. The consistency critic panel shows L↔M alignment,
set-aside↔K, and CLIN coverage (warn-only — the CO owns the publish gate, not
the model).

### Step 5 — Submit hard gate (Step 13)

Click **Submit for internal review** → the FAR 5.705 / CO-approval modal. Check
the box, confirm. Talking point: **authority over accuracy** — the model never
downgrades a hard gate; issuance requires recorded CO approval.

## Refinement / "ask the AI for more" moments

To show interactivity beyond the one-shot draft, use these in the per-section
drafting (the section card on Steps 4/6/10/11) or as edits in Step 12:

- **Regenerate a section:** on Section C/H/L/M, click the section's draft button
  again to re-run that section in isolation.
- **Add a constraint (live path):** in a section's constraints box, paste:
  - C: `Emphasize zero-trust architecture and continuous ATO; reference NIST 800-207.`
  - L: `Require a 10-page technical volume limit and a separate 2-page transition plan.`
  - M: `Weight technical approach significantly more than price; past performance as confidence factor.`
- **Tighten scope:** `Limit to CONUS performance only; remove option years beyond two.`
- **Set-aside swap demo:** change Step 1 set-aside SDVOSB → 8(a) and re-run —
  watch Section K's notice clause change.

## If something goes sideways

- **All sections empty after "Draft AI Parts":** confirm Step 1 is fully valid
  (5 required fields) — preflight 422s an incomplete batch. The batch bar button
  is disabled until Step 1 is valid.
- **503 / generation error:** the stack should be in stub mode
  (`AI_STUB_MODE=true` in compose) — no Bedrock needed. If you flipped it off,
  either set a real key in `.env` or set it back to `"true"` and
  `docker-compose ... up -d --force-recreate ai-orchestrator`.
- **Deep-link 404:** always enter via the dashboard "+ New solicitation".
- **Critic banner "did not run":** known issue (Nova Lite loops; bounded +
  warn-only). In stub mode the critic returns a clean info report, so this
  shouldn't appear; if it does, it's the documented containment, not a failure.
