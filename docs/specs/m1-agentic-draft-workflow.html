1. Multi-agent topology (ADR-0014)

Two entry paths: single-section (wizard's per-section "AI-draft" button, ADR-0012 baseline, unchanged) and batch (wizard's "Draft AI Parts" button, ADR-0014 shape). Batch path uses LangChain v1.0 Router pattern with langgraph.types.Send for parallel fan-out to per-AI-Part subagents (PartIDrafterAgent, PartIVDrafterAgent) plus two programmatic nodes for Parts II and III (no LLM call), then hands off to ConsistencyCriticAgent before wizard Step 13. Parts II + III bypass the agent topology entirely: Part II is rule-based clause selection, Part III is wizard-provided attachment metadata.

2. The four design questions, answered

A · When do we aggregate?
Two points. (1) Inside DraftingCoordinatorAgent after the parallel Send fan-out completes — assemble SolicitationDraftBundle from N FinalDraftSection returns. (2) After ConsistencyCriticAgent emits ConsistencyReport — attach to bundle for wizard Step 13 submit. No aggregation inside individual SectionDrafterAgent runs; that's a single section, no fan-in.
B · When (and whether) to run a critic pass?
Two layers, both YES. Intra-section critic = the existing validate_citations tool (programmatic, hard-fail on unknown chunk_id) — ADR-0012 D2 baseline. Cross-section critic = NEW ConsistencyCriticAgent invoked at wizard Step 12 (Review) and inside the batch coordinator before final aggregation. Validates FAR 15.204-5 L↔M alignment (semantic — LLM), set-aside ↔ Section K reps consistency (programmatic), CLIN coverage Section B ↔ C ↔ F ↔ L (programmatic). Phase 1 = warn-only (wizard renders warnings; CO can override). Hard-fail upgrade is Phase 1.5. Self-reflection / iterative critique loops are explicitly deferred — Phase 1 keeps the critic as a single non-iterative pass.
C · Do we need a coordinator / routing logic for the sections?
YES for the batch path; NO for single-section. DraftingCoordinatorAgent is a custom StateGraph (LangChain v1.0 provides no create_router / create_supervisor helper as of this fetch — only the Router pattern via Send). Routing is deterministic, not LLM-classified: section_id ∈ {C,H,L,M} AND provenance == null → spawn one SectionDrafterAgent via Send(section_id, args). No model decides which sections to draft; the wizard's per-section provenance + the M2 _FAR_SECTION_ENUM are the rule.
D · One generation phase / one-at-a-time / multi / by FAR Parts? (ADR-0014 revises)
Per-AI-Part fan-out for the batch path; per-section for the single-section endpoint. ADR-0014 supersedes ADR-0013's per-section batch fan-out after the FAR 15.204-1..5 verification:
  • Part I (A–H) — AI-drafts {C, H} together in one PartIDrafterAgent run. A/B/D/E/F/G stay human-typed in the wizard.
  • Part II (Section I — clauses) — no LLM call. Deterministic lookup on (set_aside, contract_type, agency_supplement) → required FAR clauses. Programmatic node.
  • Part III (Section J — attachments) — no LLM call. Per FAR 15.204-4, Section J is an INDEX of attachments (title/date/page count). Wizard collects metadata client-side; coordinator passes through for audit.
  • Part IV (K, L, M) — AI-drafts {L, M} together in one PartIVDrafterAgent run. Inherent L↔M alignment is built into the drafting step (the critic now verifies, doesn't enforce). K stays template + human-typed.
Fan-out drops from N=4 sections (ADR-0013) → N=2 AI-Parts (ADR-0014). Cost saving is marginal (~$0.01 input-token overhead); the real win is intra-Part coherence — C↔H share retrieved FAR context, L↔M get drafted together so misalignment is rare-by-construction. See §6 (Granularity) for the updated option table.

3. LangChain v1.0 patterns in use

Canonical v1.0 multi-agent patterns from docs.langchain.com/oss/python/langchain/multi-agent. Each pattern's role in our topology is named in "Where" below.

Router parallel dispatch multi-agent/router
Routing step classifies input → directs to specialist agents in parallel. v1.0 has no create_router helper — implemented as custom StateGraph using langgraph.types.Send. Quote: "Use Send to fan out to multiple specialized agents in parallel."
Where: DraftingCoordinatorAgent — deterministic section_id routing, not LLM-classified.
Subagents tool-wrapped agent multi-agent/subagents
Subagent registered as a @tool whose body calls subagent.invoke(...) and returns the result. Main agent maintains conversation context; subagents stateless by design. Default behavior is sequential — parallelism is explicit (Router/Send).
Where: ConsistencyCriticAgent invoked from coordinator graph node as a sub-invocation post-aggregate.
Tool-using agent create_agent agents
Single-agent harness: create_agent(model, tools, system_prompt, response_format, middleware, checkpointer). Model picks tool order from the prompt + tool descriptions; harness loops until response_format is produced.
Where: SectionDrafterAgent (existing, ADR-0012 baseline) and ConsistencyCriticAgent (new).
Critic / Reviewer single-pass validation — (composition)
Not a named v1.0 helper. Composition: a separate create_agent instance whose tools validate prior outputs. Phase 1 keeps it non-iterative (no reflection loop) — one pass, warn-only output, attached to bundle.
Where: ConsistencyCriticAgent + intra-section validate_citations tool (hard-fail layer).
HITL interrupt HumanInTheLoopMiddleware agents/middleware
Middleware interrupts agent loop before a designated tool call. Predicate reads tool_call.args (input, not return). Resume via Command(resume=...) from langgraph.types.
Where: inside every SectionDrafterAgent on the compute_gate_decision tool's hitl-band input score (ADR-0012 D6).
Structured output response_format structured-output
Pass a Pydantic BaseModel to create_agent(response_format=...); result lands in state["structured_response"]. The v1.0 idiom for agentic structured output (not with_structured_output, which is the outside-of-agents path).
Where: every agent in the topology — FinalDraftSection, ConsistencyReport, SolicitationDraftBundle.
Checkpointing MongoDBSaver langgraph-checkpoint-mongodb
Per-thread state persistence; required for HITL multi-day pause. thread_id = {solicitation_id}:{section_id}:{request_id}; coordinator threads use {solicitation_id}:batch:{request_id}. TTL=None per ADR-0012 D4.
Where: every agent instance writes to agent_checkpoints + agent_checkpoint_writes.
Handoffs NOT used multi-agent/handoffs
Agents transferring control to each other via tool calls (stateful, agent-to-user direct response). Right pattern for chat-bot ensembles; wrong pattern for our deterministic-routing fan-out + critic.
Where: not used — flagged here so it doesn't sneak in via reviewer suggestion.

5. ConsistencyCriticAgent internals

Single non-iterative pass. Three tools — one LLM (semantic L↔M alignment), two programmatic. Output is warn-only in Phase 1; wizard renders warnings inline at Step 12 but does not block submit. Hard-fail surface deferred to Phase 1.5.

L↔M coherence check. Note: FAR 15.204-5 does NOT mandate alignment in reg text (verbatim per 2026-06-10 fetch). This check enforces operational best practice + GAO bid-protest pattern, not a regulatory requirement. 7. Costs & aggregation summary

Aggregation points

  • Inside Coordinator graph (post Send fan-in): collect N FinalDraftSection from drafter subagents into SolicitationDraftBundle. Short-circuit on any outcome="interrupted" — return BatchInterrupted with all pending run_ids so wizard surfaces all CO decisions at once.
  • After ConsistencyCriticAgent: attach ConsistencyReport to bundle. Wizard Step 12 renders warnings inline. Bundle then ready for Step 13 publish-gate.
  • NOT inside individual SectionDrafterAgent: single section, no fan-in.

Critic pass invocation rules

  • Always runs inside batch path — Coordinator handles the handoff after aggregate.
  • Runs at wizard Step 12 (Review) even when sections were drafted one-at-a-time via the single-section path. Wizard POSTs /draft-solicitation/critic with the current sections bundle.
  • Phase 1 = warn-only. overall_severity rendered, never blocks Step 13 submit. Hard-fail surface = Phase 1.5.
  • No iterative reflection loop — single pass. If critic finds a warn, the CO edits + resubmits; not the agent.
  • L↔M check role depends on path (ADR-0014 D5): batch path → verify_l_m_consistency verifies that the PartIVDrafter aligned L+M (which it drafted together); standalone /critic path → full LLM semantic check on hand-typed L+M. Same tool body, different invocation context.

Parallelism summary

  • Drafter subagents run in parallel via langgraph.types.Send — wall-clock = slowest drafter (~6–10s with Sonnet), not 4× sequential.
  • HITL interrupt in one drafter does not block siblings — each writes to its own thread_id; coordinator collects whatever returns + reports interrupts on the slow ones.
  • Critic runs after aggregate, not in parallel with drafters — needs the bundle as input.
